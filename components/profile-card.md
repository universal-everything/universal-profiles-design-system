# Profile card (the UP Box)

Status: observed for anatomy, proportions and the two production hero contexts; normalized for the responsive size table and fallbacks; proposed for the share-card and OG variants and the dark theme

The UP Box is the hero of every Universal Profiles surface: a cover, a circular avatar breaking the cover's lower edge, the identicon badge at the avatar's lower right, and the name as `@name#XXXX`. It carries the Address Signature (see `../foundations/address-signature.md`) and it looks the same in the app, on the web, on a QR card and in marketing.

## Anatomy

Top to bottom:

1. **Cover.** A cover image scaled to cover, or the address gradient over `profile-card.cover-fallback`. Web height `profile-card.cover-height-web` (170); mobile full-bleed behind the panel. Share and QR controls sit at the cover's top right on the web.
2. **Avatar.** A circle from the identicon size table with a ring in `avatar.ring` (the surface colour), positioned so its vertical centre sits on the cover's bottom edge. Drop shadow `profile-card.avatar-shadow`.
3. **Identicon badge.** The address identicon at the avatar's lower right, inset by `identicon.badge-offset` (minus 1), ringed in `avatar.badge-ring`. Mandatory from `identicon.min-badge-size` (24) upwards.
4. **Name.** `@name` in `profile-card.username` (`type.mono.xl`) with the `#XXXX` suffix in `profile-card.suffix-color`. The hero name may use the username gradient (`profile-card.username-gradient-start` to `-end`). Rows use `profile-card.username-row`.
5. **Counters.** "N Following · N Followers" in `profile-card.counters` and `profile-card.counters-color`.
6. **Actions.** Web: Send and Follow. Mobile: balance pill, address pill, share and QR.
7. **Tags, links, description.** Tags as soft tags; links with monochrome social logos; description truncated in previews.

| Variant | Where | Avatar | Notes |

| Share card and OG image | Marketing and link previews | Proportional (10 percent of the width) | Generated by `signatureSvg()`; light and dark |
| Preview | Onboarding, profile switch | 96 | Same anatomy on a flat card |

Profile types: **Universal Profile** (avatar plus badge), **anonymous profile** (default person glyph on `surface.avatar-fallback`, name `anonymous-profile#XXXX`, badge shown), **externally owned account** (the identicon is the avatar, no badge, name is the truncated address), **smart contract** (the code glyph card), **token or collection** (the hexagon-cube glyph on the fallback fill).

## States

- Loading: skeleton lines for name and counters, `surface.skeleton` avatar circle; the cover shows the address gradient immediately if the address is known.
- Cover image error or missing: address gradient over the fallback fill; never an empty grey box when an address exists.
- Avatar error or missing: the fallback glyph; the badge still renders.
- Selected or active profile (multi-profile paging): page indicator dot in `page-indicator.active`.
- Pressed (rows): platform highlight; avatar hover scale `motion.scale.hover-lift` on the web.

## Sizing

Identicon table (avatar, badge, ring): 2xs 16 / 8 / 1 · xs 24 / 12 / 1 · s 40 / 16 / 2 (mobile currently 14, OPEN-06) · m 56 / 20 / 2 · l 80 / 24 / 2.5 · xl 96 / 28 / 3 · 2xl 120 / 36 / 3.5. The avatar centre sits on the cover edge, so the offset is minus half the avatar minus the ring (web: minus 103 for 120 plus 4 outline; mobile: the shipped minus 55 for 96 plus 7). Hero rings are 7 on mobile and 4 on the web; every other context uses the table ring.

Responsive: below `breakpoint.sm` the card is full width and the avatar is centred; from `breakpoint.sm` the avatar aligns left with `space.6` inset; the cover keeps a 16 to 9 crop on the web and full-bleed on mobile. Names truncate with an ellipsis before the suffix; the suffix never truncates.

## Behaviour

- Mobile panel positions: collapsed strip, half, full; drag threshold `profile-card.drag-threshold` 200; settle in `motion.duration.panel` with `motion.easing.out-expo`; expands when the browser closes; collapses on profile switch.
- Tapping the avatar opens the image (web) or the profile actions (mobile); tapping the address pill copies the checksummed address and shows a "Copied" toast.
- Counters open the followers list. The share control opens the share sheet; the QR control opens the QR card.

## Accessibility

- The card's accessible name is the display name with the suffix ("@alice#5aAe"); the badge is decorative when the name is present, and the avatar image has alt text "Profile image of @alice#5aAe" or "Default profile image".
- Cover images are decorative unless they carry meaning; never place text on the cover without the glass tier.
- Name and suffix keep 4.5:1 on canvas, card and the opaque glass tint; the gradient username must start no lighter than `gradient.username-start`.
- Avatar and badge are not colour-only signals: the name and the address pill carry the identity in text.
- Panel gestures have button equivalents (expand and collapse), and the collapsed strip is a 56 pt target.

## Platform differences

- Mobile hero sits on the glass panel with the 32 radius; the web hero is a flat card with `card.radius-s` and `shadow.card`.
- Mobile hides the panel's actions in the collapsed state; the web always shows Send and Follow.
- Android draws no glass shadow; the avatar shadow is drawn with the radius-aware shadow view.

## Status

Anatomy, sizes and offsets are observed in both products. The share-card generator, dark values and the responsive alignment rule are proposals. The badge size at the small step is open (OPEN-06); dark glass values are open (OPEN-07).

## Implementation notes

- Web: compose `lukso-card variant="dapp"` with the cover, `lukso-profile` with `has-identicon`, and `lukso-username`; apply the `--up-*` custom properties for the ring, suffix and gradient. Example: `../examples/web/profile-card.html`.
- React Native: use the shipped profile identicon (not the older profile image component, whose size table drifts), the username component with the neutral gradient, and the glass panel; read every number from the generated theme. Example: `../examples/react-native/ProfileCard.tsx`.
- Marketing: render cards from the current product or from `signatureSvg()`; never from old captures.
- Evidence: SRC-MOBILE-APP profile view, panel header, QR code screen, identicon and username components; SRC-WEB-APP profile card composition; SRC-WEB-COMPONENTS profile and username components; the brand board's highlight posts corroborate the card as the marketing hero (SRC-FIGMA-UP-BOARD 1131:27437) but show the July 2025 web card and a pre-redesign app, so they are references for composition only.
